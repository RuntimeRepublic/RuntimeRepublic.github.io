How it works: the weekly folder seal

Draft, version 0.1 · November 22, 2026

When you finish closing a week, one double-click freezes that week's folder. If any file or folder is later added, deleted or changed, a check shows exactly what. Your team sees one short code, the hashmark, and never your files.

1. Three steps

  1. Review. In your weekly deck, every tab that feeds the team packet carries a star (*). Review each one, or read the whole packet at once in the All JSON data report. Each star turns into a check mark (✓). Posting and sealing unlock only when all of them are checked.
  2. Seal. Double-click Seal This Week. It gives every file a fingerprint (SHA-256) and records every folder by name, then combines the whole list into one folder hashmark, such as #4be19a7.
  3. Check, any time. Double-click Check Seal. It recomputes everything and lists what was added, deleted or modified, or says "Sealed, unchanged."

2. What is protected: files and folders

Colors are a second cue only: every box is also labeled, and skipped items have a dashed border.

3. What the check catches

What happenedCaught?How it's reported
A file's contents changed, even by one byteYesModified
A file was added or deletedYesAdded / Deleted
A file was renamed or moved to another subfolderYesDeleted (old path) and Added (new path)
A folder was added or deleted, even an empty oneYesAdded / Deleted folder
A file was opened and closed without savingNoNothing changed, so nothing to report
A skipped housekeeping file appearedNoSkipped on purpose

Folders get their own rows in the seal list. A list of file fingerprints alone would miss an empty folder being added or removed.

4. Where the seal goes

  • Your private repository: the full seal list (every path, size and fingerprint) and the hashmark. File names can reveal which banks or bills you have, so they stay private.
  • Your team's repository: one small text file next to your packet with the week, your call sign, the counts, the folder hashmark and the packet's own fingerprint. No file names, dollar amounts or account numbers.
Why GitHub matters. A seal kept only on your computer could be quietly redone. Committing the hashmark to GitHub gives it an outside timestamp, so anyone can see when seal v1 existed and that any later seal came after it.

5. Rules that keep it honest

  • Seal last. Finish the deck, packet and workbook first, then seal.
  • Corrections are allowed and visible. If something must change after sealing, you make seal v2 with a one-line reason. Seal v1 stays in the folder and on GitHub.
  • Opening and saving a file counts as a change. That's correct. Open sealed files read-only.
  • The scripts only read and fingerprint. They never delete, move or change your files, and they never touch your money or accounts.
  • A seal detects changes; it does not prevent them. Your files stay yours to edit. The seal just makes every change visible.

Fingerprints use SHA-256: the sorted lines type|path|bytes|fingerprint, joined and fingerprinted again, give the folder hashmark. Windows PowerShell's built-in Get-FileHash does the file fingerprints.
